# 업무 프롬프트 작성 위치

프로젝트의 업무 목표·입력·출력·성공 조건·실패 처리를 정의하고 제공된 실행 기반에 연결합니다. 이 문서는 프롬프트 작성 안내이며 프롬프트·모델 설정·문맥 처리 코드는 업무에 맞게 수정할 수 있습니다. 현재 스켈레톤은 이 문서를 모델에 자동 전달하지 않습니다.

업무 처리 함수에서 프롬프트와 파일 참조 목록, 필수 config를 지정해 callLLM을 명시적으로 호출합니다. 도구 호출과 자료 수집 순서는 선언한 노드 경로와 업무 코드로 정합니다. 모델에는 그 경로에서 확보한 입력과 해당 노드의 판단 작업을 전달합니다. 생성 요청은 함수 호출당 한 번이며, 노드 단위 재시도는 `NodeSpec.policy`로 선언합니다.

작성 기준은 [프롬프트 스킬](../.agents/skills/agent-prompt-writing/SKILL.md)에 둡니다. 아래에서는 실제 연결 위치와 단계별 입력 구성을 설명합니다.

기본 업무 함수는 `initial_planner`에서 즉시 응답·Clarification·등록된 업무 진입 노드 중 하나를 선택합니다. 최초 플래너의 실제 프롬프트는 `python/simple_agent/planner.py`의 `PLANNER_PROMPT`이며, `stage_prompts[NodeKind.PLANNING]`으로 연결합니다. 현재 설정은 OpenAI Responses·`gpt-6-luna`·입력 50000토큰·출력 1000토큰·thinking high입니다. 제너레이션의 입력 설정은 `max_input_tokens=None`으로 명시합니다. 아직 업무 제너레이션 노드는 없으며 추가 시 적용합니다. 공통 호출 기본값이 아닙니다.

플래너는 이번 턴의 발언, 보류 작업, 파일 메타데이터만 받습니다. 파일 내용과 전체 과거 대화는 자동으로 넣지 않습니다. 선택 후보는 개발자가 선언한 노드의 설명·입력 규격입니다. 인사·일상·불명확한 문자열·인젝션·미구현 업무 안내는 즉시 응답하고, 작업이나 대상이 불명확하면 구체적인 질문을 생성합니다. 두 응답 노드는 플래너의 문자열을 그대로 반환합니다.

업무 노드·하위 노드의 프롬프트와 호출·직렬/병렬 조합·결과 종합은 개발자가 작성합니다. `prompt_template`은 명시적 `callLLM` 호출의 사용자 prompt 앞에 붙으며, `ctx.services.node_prompt`로도 읽을 수 있습니다. 단계 공통 시스템 지시는 `stage_prompts`, 리트리벌의 시스템 지시는 `NodeSpec.system_prompt`로 선언합니다. 선언만으로 모델을 호출하지 않습니다. 노드 타입·허용 경로·단계별 도구·보류 작업과 하위 실행 API는 [노드 가이드](../docs/workflow.md)를 따릅니다.

## 단계별 작성 규칙

OpenAI Responses의 planning·generate 문맥은 자동 연결하며 Clarification은 기존 보류 작업과 함께 저장·복원합니다. 명시적 캐시 경계·보존 시간 옵션은 아직 연결하지 않았습니다. 사용법과 지원 범위는 [단계별 프롬프트와 문맥 계약](../docs/workflow.md#단계별-프롬프트와-문맥-계약)을 따릅니다.

- **planning:** 단계 공통 시스템 프롬프트에 업무·후보·판단 기준을 작성합니다. 노드마다 결정할 사항과 새 정보를 사용자 메시지로 추가하며, 어떤 업무를 위해 어떤 리트리벌을 선택할지 확정할 때까지 같은 작업의 대화를 유지합니다. Clarification의 추가 답변도 이어 붙입니다.
- **retrieval:** 각 LLM 호출의 시스템 프롬프트와 사용자 프롬프트를 설계합니다. 시스템에는 자료 확인 작업·근거 반환 기준을, 사용자 입력에는 확정된 목표·조건·이번에 볼 자료를 넣습니다. 이전 LLM 대화 없이 호출마다 새 입력을 사용합니다.
- **generate:** 단계 공통 시스템 프롬프트에 답변 작성·근거 사용 기준을 작성합니다. 리트리벌 결과와 답변 목표로 새 문맥을 시작하고, 같은 답변 작업의 후속 노드 지시를 사용자 메시지로 추가합니다. 플래닝 대화 전체는 자동으로 옮기지 않습니다.

문맥을 유지하는 단계는 기존 메시지·모델 출력·도구 결과의 순서를 유지합니다. 고정 시스템 프롬프트와 기존 앞부분은 캐시 재사용 대상이며, 캐시 적중 여부와 관계없이 필요한 문맥을 실제 요청에 전달합니다. 시스템 프롬프트를 캐시 길이에 맞춰 불필요하게 늘리거나 노드 지시로 매번 교체하지 않습니다. 재시도 시 실패한 시도의 단계 문맥은 진입 전 상태로 복원하고, 보완할 정보는 새 노드 입력으로 전달합니다. 전체 시도 원문은 실행 기록에 남깁니다. 완료·종료 판정과 재시도 설정은 [노드 실행 계약](../docs/workflow.md#노드-완료종료재시도)에 둡니다.
