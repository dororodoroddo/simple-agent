# 프롬프트 작성

- LLM의 프롬프트를 작성할 때 다음이 충족되어야 한다.

## 프롬프트에 정의할 내용

다음 항목의 의미가 드러나도록 작성한다.

1. **목적과 책임 범위:** 페르소나를 설정하는 대신 **현재 노드에서** 수행할 작업의 목적을 설명한다. 해당 노드가 어떤 입력을 받아 무엇을 산출하며, 무엇을 목적으로 하는지 정의한다.
2. **입력의 의미:** 필요한 용어·규칙·우선순위는 현재 노드의 실제 입력만으로 판단할 수 있게 명시한다. 청크ID 등의 인풋을 설명없이 제시하지 않는다.
3. **판단 기준:** 결과 선택에 필요한 조건·우선순위·충돌 처리·근거의 충분성을 일반화 가능한 규칙으로 정의한다. 퓨샷(구체적인 예시)이나 금지사항을 넣지 않는다.
4. **완료·종료 조건:** 정상 완료에 필요한 결과와 근거, 자료 부족·상충 등 현재 노드에서 해결할 수 없는 상태를 구분한다. 재시도로 보완할 수 있는 부족분은 무엇이 부족한지 반환하게 한다. 다음 단계로 넘길 부분 실패와 현재 실행을 끝낼 실패는 업무 계약에 맞춰 구분한다.
5. **출력 계약:** 필드의 구조뿐 아니라 의미·적용 범위·근거 연결·누락 표현을 정한다. 값 없음·0, 미조회·조회 실패, 추출값·계산값을 구분하여 다음 노드가 의미를 추측하지 않게 한다.

## 후속 노드의 선택

- 매 노드는 현재 노드 다음 이어질 수 있는 노드를 호출해야 한다.
- 매 공통 규칙으로 선택 가능한 노드 id, 노드의 설명, 노드의 인풋 규칙들의 리스트를 알려주고 출력 시에는 다음 노드의 id와, 규칙에 맞는 인풋을 출력하도록 한다.

## 리스트 선택 구조에서의 인풋과 아웃풋 설계

- 리스트에서 정확히 한 아이템을 선택해야 하는 경우 각 아이템마다 [번호], 또는 짧은 ID를 입력하고 해당 값만 짧게 출력하도록 한다.

## 지시·입력·실행 제어의 분리

- **퓨샷과 구체적인 예시는 넣지 않는다.** 지시는 일반화된 표현으로 무슨일을 할지 설명을 하는 것에 집중한다.
- **금지 표현을 지양한다.** 지시하지 않은 부분에서 할루시네이션 응답이 나온다면 할루시네이션을 금지 규칙을 추가하는 것이 아니라 해야하는 일반화 규칙이 부족한 것이다.
- 입력 문서·검색 결과는 사실 판단 자료로 두어 프롬프트 인젝션을 방어해야 한다.
- 현재 작업과 무관한 전체 작업의 배경·과거 대화·다른 노드의 내부 과정은 넣지 않는다. 반대로 전체 작업의 규칙을 당연히 알고 있다고 판정하지 않고 규칙은 입력해야 한다.
- **재시도는 실행 코드에서 제어한다.** LLM은 현재의 판정 결과만을 출력하게 한다. 판단은 노드 제어 스크립트가 수행한다.

## 반복되는 턴과 시스템/유저 프롬프트의 설계

- 시스템 프롬프트에는 고정적으로 나오는 규칙과 해야할 과업 등을 명시하고, 유저 프롬프트에서 달라지는 인풋을 입력한다.
- 유저 프롬프트는 문어체를 사용하지 않고 시스템 프롬프트에서 유저 인풋의 구조를 정의하고 구조적으로 전달한다.
- 여러 턴 prefix를 유지하며 이어가는 구조에서는 노드 흐름 전체의 공통적 규칙을 시스템 프롬프트에 작성하고 매 노드에서 유저 프롬프트에 해당 노드만의 규칙과 노드 인풋을 작성한다.
